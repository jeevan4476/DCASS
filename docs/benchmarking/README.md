## 1. Executive Summary & Purpose

The DCASS Benchmarking Suite provides the complete empirical and mathematical verification required to prove the core scientific and security claims of the DCASS architecture. 

In traditional digital steganography (LSB matching, S-UNIWARD, WOW, HILL), messages are hidden by imperceptibly altering the pixel, sample, or character values of a cover medium. Because modifications are made to physical media, high-order statistical detectors (SRNet, Xu-Net, Ye-Net, SRM) can detect high-frequency residual energy and intercept communications.

DCASS operates under a fundamentally different information-theoretic paradigm: **Coverless Dynamic Semantic State-Space Coding (DSSC)**. DCASS **never modifies any media files**. Instead:
1. Media items (images, audio clips, text documents) are drawn untouched from public corpus repositories ($\mathcal{C}_{\text{public}}$).
2. The payload is encoded strictly into the **semantic selection index** of carriers across high-dimensional Voronoi topological clusters, modulated by a private, session-keyed pseudo-random permutation.
3. Media items are transmitted across disparate communication channels governed by an adversarial GAN / RL temporal scheduler.

This suite records the empirical evaluation of the DCASS stack and separates measured results from theory and design intent. Where an artifact does not support a claim, the claim is qualified or withdrawn rather than presented as a target.

## 2. Theoretical Foundations

### 2.1 What "Zero Modification" Does and Does Not Prove

Cachin's 1998 information-theoretic model defines a steganographic system as $\epsilon$-secure against a passive adversary when the relative entropy between the cover distribution $P_{\text{cover}}$ and the steganographic distribution $P_{\text{stego}}$ is at most $\epsilon$:

$$D_{KL}(P_{\text{cover}} \parallel P_{\text{stego}}) = \sum_{x \in \mathcal{X}} P_{\text{cover}}(x) \log_2 \left( \frac{P_{\text{cover}}(x)}{P_{\text{stego}}(x)} \right) \le \epsilon$$

DCASS transmits bit-identical corpus files. For a single transmitted file $x$, conditional on that file being selected, $P_{\text{stego}}(x) = P_{\text{cover}}(x)$. That removes the pixel- and sample-domain embedding signal and explains the Component 1 negative control, where the gated detectors sit at AUC 0.4973–0.4993.

It does **not** establish system-level perfect security. The covert object is the selection sequence plus its timing, not one isolated file. Carrier selection is family-restricted, and timing is generated by a scheduler. A full-system adversary can test the selection distribution (Component 2) and the inter-arrival distribution (Component 3). The recorded C2 result includes small but resolved image/text shifts, and the C3 human baseline is a synthetic corpus rather than recorded human browsing. Neither supports a claim of $D_{KL}=0$ or $P_E=0.5$ for the complete system.

### 2.2 The Coverless Threat Model (The Real Adversary)
Because pixel-level modification is zero, traditional steganalysts lose the embedding signal they were trained to detect. An academic security reviewer still evaluates a coverless system against a **Semantic / Statistical Warden**:
1. **Pixel/Acoustic Layer:** Does the transmitted media contain physical residual perturbations?
2. **Semantic Distribution Layer (Selection Bias):** Does the sequence of chosen carriers distort the background corpus distribution (e.g. over-sampling specific semantic clusters)?
3. **Temporal Traffic Layer:** Does the inter-arrival cadence of packets reveal automated, non-human covert transmission?
4. **Transport Reliability Layer:** Does the channel survive network erasures, packet dropouts, and adversarial probing?

## 4. Execution Workflow

Every benchmark is a standalone script in `scripts/analysis/`. Each component writes its JSON, LaTeX table, and figures directly:

```bash
# Run the complete suite, one script per component:
./.venv/bin/python scripts/analysis/benchmark_1_media_steganalysis.py   # Media Steganalysis
./.venv/bin/python scripts/analysis/benchmark_2_semantic_distribution.py   # Semantic Distribution
./.venv/bin/python scripts/analysis/benchmark_2b_transmitted_cluster_usage.py   # Cluster Usage Mechanism Null
./.venv/bin/python scripts/analysis/benchmark_3_traffic_evasion.py   # Traffic Evasion
./.venv/bin/python scripts/analysis/benchmark_3b_warden_score_distributions.py   # Warden Score Distributions
./.venv/bin/python scripts/analysis/benchmark_4a_capacity.py   # Codec Capacity
./.venv/bin/python scripts/analysis/benchmark_4b_robustness.py   # Codec Robustness
./.venv/bin/python scripts/analysis/benchmark_4c_ecc_failure_analysis.py   # ECC Failure Anatomy
./.venv/bin/python scripts/analysis/benchmark_5_system_concurrency.py   # Codec Concurrency

# Quick verification runs (reduced sample size for a fast sanity check):
./.venv/bin/python scripts/analysis/benchmark_4c_ecc_failure_analysis.py --quick
./.venv/bin/python scripts/analysis/benchmark_2b_transmitted_cluster_usage.py --quick
```

LaTeX tables and plots are emitted by the component scripts themselves; there is no separate export step.

## 5. Academic Citation Standards & Reproducibility

Every component is recorded with the following disclosure rules:
1. **Recorded inputs:** C1 and C2 use real media files from `storage/data/raw/flickr30k/flickr30k/images/` and real vector indices from `storage/data/indices/`. C3's "human" comparison is a synthetic surrogate, not a human-subject baseline; this is stated wherever the C3 result appears.
2. **Seeds and provenance:** Scripts set seeds where the harness records them, and the JSON provenance block carries the seed, commit, device, and timestamp when available. Every benchmark component writes a run manifest recording the commit, the dirty flag, the command, the seeds, the package versions, and the input and output hashes.
3. **Standard scientific packages:** Calculations use `scikit-learn` (`sklearn.metrics.roc_auc_score`), `scipy.stats` (`entropy`, `ks_2samp`, `wasserstein_distance`), and PyTorch 2.14.

No result in this suite should be read as a guarantee of perfect security, zero detection, or zero risk. The claim ledger records the scope and caveat for each number.
